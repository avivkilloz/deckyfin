## Architecture Background

### App ID Calculation
Steam generates app IDs for non-Steam shortcuts via: `CRC32(exe + app_name) | APPID_CRC32_MASK`.
- `calc_shortcut_app_id()` in `steam_games.py` implements this
- `convert_appid_to_unsigned_32bit()` converts signed → unsigned
- `convert_appid_to_config_format()` converts to 64-bit for CompatToolMapping

### Two Types of App IDs
1. **`steam_app_id`** — manual Steam Store app ID (e.g., 1222680 for BG3). Used ONLY for dependency lookup via ProtonDB/WineDB. NOT used for Steam shortcut detection.
2. **`shortcut_app_id`** — the CRC32-generated app ID from shortcuts.vdf. Saved to config for prefix tracking. Detection is name-based only.

### Key Files
- `py_modules/steam_games.py` — VDF read/write, app_id calculation
- `src/components/GameDetail.tsx` — "Add/Update Steam" buttons, config persistence
- `src/components/GameLibrary.tsx` — library view, Steam detection badges

### Update Flow
```
GameDetail.tsx: handleUpdateSteam()
  → updateSteamShortcut(name, executable, startDir, launchOptions)
  → main.py: update_steam_shortcut()
    → resolves relative paths against games_folder
    → update_nonsteam_game(app_name, resolved_exe, resolved_start, launch_opts)
      → finds shortcut by AppName match in shortcuts.vdf
      → updates Exe, StartDir, LaunchOptions
      → PRESERVES existing appid (does NOT recalculate)
      → saves shortcuts.vdf
  → returns { success, app_id, unsigned_appid }
  → Frontend saves shortcut_app_id to config
```

### Add Flow (when game NOT in Steam)
```
GameDetail.tsx: handleAddToSteam()
  → addSteamShortcut(executable, name, startDir, launchOptions)
  → main.py: add_steam_shortcut()
    → add_nonsteam_game()
      → checks for existing shortcut by AppName
      → if exists: update in-place (preserves appid)
      → if new: creates with calc_shortcut_app_id()
      → saves shortcuts.vdf
```

## App ID Algorithm Quirks
- Steam's `appid` field in shortcuts.vdf is NOT the same as the CRC32-derived ID for shortcuts created by tools like Heroic/Lutris
- Recent fixes prefer the stored VDF `appid` over recalculation to avoid mismatches
- `config_appid` (64-bit format for CompatToolMapping) is derived from the stored appid

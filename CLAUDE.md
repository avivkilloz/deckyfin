## What This Is

Deckyfin is a [Decky Loader](https://decky.xyz) plugin for Steam Deck / Desktop Linux. It manages local or home-server Windows games — adding them to Steam as non-Steam shortcuts, configuring Proton versions, initializing Wine/Proton prefixes, installing dependencies via winetricks/protontricks, and applying SteamGridDB artwork.

## Commands

```bash
# Build frontend (Rollup bundle → dist/)
npm run build

# Watch frontend for changes

# Run backend tests

# Run a single test

# Format (Python + TypeScript)

./deploy.sh

journalctl -u plugin_loader.service -f

cat /home/deck/homebrew/plugins/deckyfin/debug.log
```

## Architecture

The plugin has two layers that communicate via Decky IPC:

**Frontend** (`src/`) — React 18 + TypeScript, bundled with Rollup.
- Entry point: `src/index.tsx` registers the plugin and renders `<GameLibrary />`
- `callable<[ArgTypes], ReturnType>("backend_method")` from `@decky/api` creates typed proxies to Python methods
- `@decky/ui`'s `Focusable` wraps every interactive element for gamepad navigation

**Backend** (`main.py` + `py_modules/`) — Python, runs inside the Decky Loader sandbox.
- `main.py` — the `Plugin` class; every public `async def` is a callable endpoint. A post-class wrapper auto-logs every call and exception to `debug.log`.
- `py_modules/` — separated modules: `deckyfin_config.py` (JSON game config store), `steam_games.py` (VDF shortcuts read/write, app_id calculation), `deckyfin_proton_compat.py` (CompatToolMapping), `deckyfin_prefix.py` (prefix init), `deckyfin_protontricks.py` (dep installation with 4-method fallback chain), `deckyfin_steamgrid.py` (SteamGridDB API), `steam_utils.py` (Steam root, user ID).

## Key Concepts

**App ID duality:** Two unrelated IDs co-exist per game.
- `steam_app_id` — the Steam Store ID, set manually, used only for ProtonDB/WineDB dep lookup.
- `shortcut_app_id` — CRC32 of `(exe + app_name)`, generated by Steam for non-Steam shortcuts. Used for prefix paths and artwork. Computed by `calc_shortcut_app_id()` in `steam_games.py`.

**Needs-restart persistence:** Decky re-mounts the plugin UI on every sidebar open, which resets all React state. Any flag that must survive navigation is stored backend-side: `needs_restart` as a flag file (`<app_folder>/needs_restart`), per-game flags (`needs_restart_after_add`, `needs_restart`) in the game's JSON config, and in-progress install state (`processing_state`) also in the JSON config.

**Green button state:** Action buttons turn green when there's pending work. Driven by three snapshot comparisons in `GameDetail`:
- `configDirty` — current form fields vs `configSnapshot` (last saved config)
- `steamNeedsSync` — `configSnapshot` vs `lastSyncedSnapshot` (what's currently in Steam)
- `depsNeedsInstall` — `configSnapshot.proton_dependencies` vs `lastInstalledDeps` (what was last installed)

All three snapshots are persisted in the game config (`steam_snapshot`, `deps_snapshot`) and restored on mount.

**Focusable picker items (gamepad UX):** Every item inside a scrollable picker (exe picker, proton picker, folder browser) MUST have `margin: "0 2px"` and `padding: "4px 10px"`. Without this, Decky's `is-focused` blue outline clips at the edges.

**Debug logging:** Use `_debug(f"context: var={val!r}")` in `main.py` — writes to `debug.log` in the plugin directory (`/home/deck/homebrew/plugins/deckyfin/debug.log`).

**Three path concepts per game:**
- `game.path` — the game's root folder under `games_folder` (used as the scan root for exe picker)
- `executable` — full path to the `.exe`
- `start_dir` — working directory when launching (not the same as game root)

**callable name collision:** If a `callable()` proxy name matches a React `useState` setter, rename the state setter with a `State` suffix (e.g. `setNeedsRestartState`).
